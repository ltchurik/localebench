# localebench

**Do LLMs write like a native?** A benchmark of locale conventions and formal register in model *output* across European languages.

[![ci](https://github.com/ltchurik/localebench/actions/workflows/ci.yml/badge.svg)](https://github.com/ltchurik/localebench/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

> **🚧 Early development — no published results yet.** The harness, the task format and a seed set of 40 tasks in 5 languages work today. The leaderboard comes after the task set is reviewed by native speakers.

Ask a model in Slovak, German or French for a price, a date or a quote and you often get English conventions dressed in local words: `€1,234.50`, `2026-03-05`, `3.7%`, `"straight quotes"`, or a casual *tu* / *du* / *ty* to a customer. A native reader spots it in a second. Most multilingual benchmarks never look.

localebench checks whether the text a model **generates** follows the conventions of the target locale:

| Category | What is checked | Example (sk) |
|---|---|---|
| `date`, `date_long` | numeric and written-out date formats, month declension | `5. 3. 2026`, `14. októbra 2026` |
| `money`, `money_large` | decimal comma, thousands separator, currency position | `1 234,50 €` |
| `percent`, `decimal` | decimal comma, space before `%` where the norm requires it | `3,7 %`, `21,5 °C` |
| `quotes` | native quotation marks | `„…“` (sk/cs/de), `„…”` (pl), `« … »` (fr) |
| `register` | formal address to an unknown customer | *vykanie*, *Sie*, *Pan/Pani*, *vous* |

Seed languages: **Slovak, Czech, German, Polish, French** (8 tasks each). More languages are welcome; see [Contributing](#contributing).

## Why it matters

- **Production text.** Invoices, e-mails, support replies and e-shop copy generated by LLMs go straight to customers. Wrong number formats are not cosmetic: `1.234` means one thousand in German and one point two in English.
- **Trust.** Formal address is a social contract in most European languages. A support bot that says *du* to a customer sounds wrong, however good its grammar.
- **Nobody measures it.** Existing benchmarks test knowledge and understanding, not whether the output looks native.

## Method

- **Tasks are written natively per language**, not translated. Each prompt gives the data in a neutral or English form (`total = 1234.5 EUR`, `delivery_date = 2026-03-05`) and asks for a sentence for a local reader, so the model has to choose the convention itself.
- **Deterministic checks only** (regex), no LLM judge. A task passes only if all its checks pass.
- **Every task is self-tested**: it ships a `reference` answer that must pass and a `counterexample` (the typical English-convention mistake) that must fail. `localebench validate` and CI enforce both.
- **Lenient where the norm is lenient.** Where a language accepts several forms (e.g. `05.03.2026` and `5. März 2026` in German), all of them pass.
- **Optional linting with [llm-locale-lint](https://github.com/ltchurik/llm-locale-lint)**, a CLDR-based checker for generic locale issues (e.g. no-break spaces, typographic quotes) in any text. In this version its findings are reported for information only; `--lint strict` makes them affect pass/fail.
- Any **OpenAI-compatible API**: OpenAI, OpenRouter, Ollama, vLLM, LM Studio, llama.cpp server. Temperature 0 by default.

## Quickstart

```bash
pip install git+https://github.com/ltchurik/localebench
# or, from a checkout:  pip install -e .

localebench validate                     # checks the task files

export LOCALEBENCH_API_KEY=sk-...        # or OPENAI_API_KEY
localebench run --model gpt-4o-mini --base-url https://api.openai.com/v1 --langs sk,cs,de,pl,fr

# local model via Ollama, no key needed
localebench run --model qwen3:8b --base-url http://localhost:11434/v1 --langs sk,de

localebench report                       # markdown leaderboard from results/*.json
```

Each run writes `results/<model>.json` with every prompt, answer and check result, so a score can always be traced back to the exact text.

With llm-locale-lint installed (`pip install "localebench[lint] @ git+https://github.com/ltchurik/localebench"`), its findings are added to each task automatically.

## Task format

`tasks/<lang>.jsonl`, one task per line:

```json
{"id": "sk-money-003", "lang": "sk", "category": "money",
 "prompt": "Napíš zákazníkovi jednou vetou, koľko zaplatí: total = 1234.5 EUR",
 "checks": [{"type": "regex", "value": "\\b1 ?234,50? ?(€|eur\\b|EUR\\b)"},
            {"type": "not_regex", "value": "1,234\\.5|1234\\.5|€ ?1"}],
 "reference": "Celkovo zaplatíte 1 234,50 €.",
 "counterexample": "Celkovo zaplatíte €1,234.50."}
```

Check types: `regex`, `not_regex`, `contains`, `not_contains`, `min_words`, `max_words`. Answers are normalized before checking (NFC, Markdown emphasis removed, all no-break space variants folded into a plain space).

## Prior art

localebench complements these rather than replacing them:

- **[EuroEval](https://euroeval.com/)** (formerly ScandEval): broad European-language benchmark of knowledge, understanding and generation tasks.
- **Marco-Bench-MIF**: a localized IFEval across 30 languages; tests instruction following, not locale conventions.
- **Global-MMLU**: culturally adapted multilingual knowledge evaluation.
- **[sk-llm-eval](https://github.com/ltchurik/sk-llm-eval)**: the author's Slovak-only benchmark of grammar, register, formatting and facts. localebench generalizes its formatting and register categories to more languages.

As far as I found (November 2026), none of these scores the date, number, currency, quotation and register conventions of the text a model generates. If you know of one, please open an issue.

## Contributing

Native speakers are the most valuable contributors. To add or fix tasks:

1. Edit or create `tasks/<lang>.jsonl` (prompts written in the language, not translated).
2. Give every task a `reference` that a careful native writer would produce and a `counterexample` showing the typical mistake.
3. Run `localebench validate` and `pytest`.

Please cite the norm you rely on (e.g. a national style guide or orthography handbook) in the pull request.
